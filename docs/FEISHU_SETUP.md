# 飞书接入与首次真实验证

本项目使用企业自建应用的机器人读取指定群历史消息，在本机生成报告。无需公网地址、事件回调、Webhook 或长连接订阅；首版由用户手动同步和生成。

## 1. 创建应用并启用机器人

进入 [飞书开放平台开发者后台](https://open.feishu.cn/app)，创建企业自建应用，按页面要求填写基本信息并开启机器人能力。在“凭证与基础信息”取得 App ID 与 App Secret，留在本机配置。

使用应用机器人，不使用群自定义机器人的发送 Webhook。仅有 Webhook 地址不能用于本项目的群历史消息读取。[官方机器人概述](https://open.feishu.cn/document/client-docs/bot-v3/bot-overview) 区分机器人能力与应用接口。

## 2. 申请读取权限并发布

在应用的权限管理中申请与下列接口对应的应用身份权限。飞书后台的显示名称可能调整，优先按权限标识和官方接口页核对。

| 用途 | 所需权限 |
| --- | --- |
| 读取历史消息的基础权限 | `im:message:readonly` |
| 应用身份读取机器人所在群全部消息 | `im:message.group_msg`，需与上一项配合 |
| 列出机器人已加入的群 | `im:chat:read` |
| 可选：读取所选群成员名称 | `im:chat.members:read`；消息读取与本机备注不依赖此项 |

群消息的前两项组合来自 [官方获取会话历史消息文档](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/message/list)。群列表的 `im:chat:read` 经 [飞书官方 CLI 文档](https://github.com/larksuite/cli/blob/main/skills/lark-im/references/lark-im-chat-list.md)的应用令牌权限说明交叉核对，也可在[群列表接口页](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/chat/list)查看当前可选权限。仅有“接收群内 @机器人消息”权限不足以读取群内全部历史消息。首版不需要发送消息、通讯录、云文档或多维表格写入权限。

创建应用版本并申请发布，按所在企业要求完成管理员审核；在应用可用范围与所授数据范围中确保测试使用者和目标场景可用。修改权限后，要核对当前发布版本和实际授权是否已经生效。发布并添加机器人的操作可参考 [飞书官方机器人配置示例](https://www.feishu.cn/practice_template/51118)。

### 可选的成员名称读取

[获取群成员列表](https://open.feishu.cn/document/server-docs/group/chat-member/get)可以按 `open_id` 返回成员 ID 和 `name`，无需为这个用途申请整份通讯录或手机号权限。操作者须在所选群内，应用需要机器人能力；内部群要求操作者与群同租户，返回列表不包含机器人。`name` 仅作为飞书返回的成员名称使用，不保证等同于群昵称。

当前本机最初只有三个基础读取权限，成员列表曾返回 `99991672`。用户随后明确确认唯一新增的应用身份权限 `im:chat.members:read`，现已开通；后台显示“当前修改均已发布”，该免审权限立即生效，无需另行创建版本。指定内部群已实际读取到 2 位成员名称：本人官方名称“李成龙”，本机昵称和报告显示仍为“船长”；另一位为“种楠”。既有本人身份、成员备注、常用设置及原报告保持原样。

新环境如需自动姓名，可申请上述最窄群成员读取权限，按后台要求完成审批与发布，并在“成员与事项”点击“刷新飞书名称”核对实际结果；是否需要新版本以后台显示为准。不要因姓名查询失败重复申请已有三个消息权限，也不需要扩大为全企业通讯录读取。本次未申请全通讯录权限，未发送消息。

没有这项可选权限也能继续同步和生成。在“成员名称与本机备注”中保存备注即可；它只修改本机展示，不修改飞书资料、不认证本人身份，也不覆盖历史报告。界面只为当前所选群刷新姓名，姓名读取失败与消息读取结果分别提示。

## 3. 邀请机器人入测试群

先使用一个允许读取的测试群。在飞书群的设置中找到“群机器人”，添加刚创建的应用机器人。机器人需要在被查询群中，这是历史消息接口的前置条件。

随后由你本人在群中发送几条便于核对的文字，例如一项已完成事项、一项阻塞、一项下一步计划；再请另一位成员发送一条不同内容，用于验证个人汇报不会混入他人的消息。应用身份不能因此读取任意员工之间的私人聊天。

## 4. 本机配置

按工程 README 将 `.env.example` 复制成 `.env`，在本机文本编辑器填写：

```dotenv
FEISHU_APP_ID=你的自建应用_App_ID
FEISHU_APP_SECRET=你的自建应用_App_Secret

# 可选。留空即可先用本地摘录生成报告。
LLM_BASE_URL=https://api.openai.com/v1
LLM_API_KEY=
LLM_MODEL=

# 可选，本地端口和数据目录。
APP_PORT=8765
DATA_DIR=data
```

占位文字不能直接连接。App Secret、访问令牌与模型 Key 不需要发到聊天窗口，也不应写进浏览器表单、前端文件、报告或 Git 仓库。本项目服务端读取凭证；修改 `.env` 后重启服务。

不配置模型 Key 和模型名时使用本地模板和证据摘录，不产生模型调用费用。模型接口地址填写基础 API 地址（例如以 `/v1` 结尾），程序会拼接 `/chat/completions`。配置模型并选择调用后，所选消息会发给你配置的模型服务；先用测试群确认其接口兼容性和报告质量。

## 5. 第一次完整验证

1. 按 README 启动程序，打开本机控制台，确认地址是 `http://127.0.0.1:8765`，或你配置的端口。
2. 查看配置状态，加载飞书群列表；找到测试群。如果看不到群，先核对机器人入群、应用发布与权限生效情况。
3. 选择真实飞书来源、测试群与包含刚才消息的日期，手动同步。
4. 生成项目日报，逐条对照测试群。确认日期、群、提取消息数、引用依据以及工作状态都正确。更改汇报日期或周期后，应先同步新的完整区间；本地已有消息不能证明所有日期与群都已覆盖。
5. 选择个人汇报，从已导入消息的发送者中选择你本人的 ID。对照群消息核实该 ID；其他成员的工作不能出现在个人成果中。
6. 生成周报和月报，检查周期范围，再下载 Markdown。周从周一开始，月按自然月，均为上海时间。
7. 对相同范围再次同步，确认数据没有重复增长。切换演示来源时，报告应明确标识示例；真实报告不得包含演示内容。

## 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 未配置或凭证无效 | `.env` 文件名、App ID/Secret 是否属于同一个自建应用、修改后是否已重启 |
| 在群里搜索不到机器人 | 核对客户端当前组织和添加人是否在应用可用范围内、群是否为外部群；外部群需要相应共享能力，群也可能限制仅群主或管理员添加。见[飞书官方群机器人说明](https://www.feishu.cn/hc/zh-CN/articles/360024984973-在群组中使用机器人) |
| 群列表为空 | 应用机器人是否已入群、机器人能力是否开启、群列表权限是否生效 |
| 群存在但读取无权限 | 是否同时开通基础历史读取与 `im:message.group_msg`，发布与审核是否生效 |
| 同步成功但没有消息 | 所选群、日期和上海时区；飞书实际返回范围；消息是否在该时间内 |
| 个人汇报没有内容 | 所选发送者 ID 是否对应本人、本人是否在所选群和日期内发送了可提取文字 |
| 新环境成员名称查询返回 `99991672` | 核对 `im:chat.members:read` 是否已授予并生效，或继续使用本机备注；本机这项历史问题已通过用户确认后的单项授权与发布解决 |
| 图片/文件中的工作未被总结 | 首版只提取文本与可提取的富文本，未读取图片、附件、语音、卡片、合并转发和话题回复；链接也不代表已读其正文 |
| 网络超时或限流 | 后台会有限重试短暂故障，并遵守可接受等待范围内的官方限流提示；若等待过长会停止并提示稍后重试。状态未知时先“继续查看进度”，勿重复提交；保留错误码帮助排查，勿粘贴密钥或完整令牌 |

## 接口核对与验证状态

截至 2026-10-21，已核对官方 [获取自建应用访问令牌](https://open.feishu.cn/document/server-docs/authentication-management/access-token/tenant_access_token_internal)、[群列表](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/chat/list)、[历史消息](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/message/list)、[群成员列表](https://open.feishu.cn/document/server-docs/group/chat-member/get)和[频率控制](https://open.feishu.cn/document/ukTMukTMukTM/uUzN04SN3QjL1cDN)文档。本 Demo 调用 `/open-apis/auth/v3/tenant_access_token/internal`，读取 `tenant_access_token` 与 `expire` 并缓存访问令牌。飞书也提供 [新版 OAuth 应用令牌接口](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/authentication-management/access-token/tenant_access_token)，其响应字段是 `access_token` 与 `expires_in`，不要将两套响应字段混用。

未配置真实凭据时，只能验证本地流程和模拟接口。配置凭据后，仍需完成上面的真实测试群流程才能确认消息读取和报告结果；应用审批、可见数据范围和历史消息可访问性以飞书实际结果为准。本机最新配置与连接结果见 [配置进度](SETUP_PROGRESS.md)。
